# Scale-up plan

Scale only when new information justifies the cost. Row count is capacity, not
success.

## Stages

1. Keep the 260 authored semantic families as the reviewed core. Run the
   64-case set-cover diagnostic during ordinary parser work.
2. Expand to thousands of blueprints by adding reviewed semantic combinations:
   operation targets and stored-item context, temporal scope, shared context,
   ambiguity policies, multi-item order, and safety-critical polarity. Reject
   duplicates by canonical semantic hash before rendering.
3. Expand to tens of thousands only through reviewed product contracts and
   explicitly licensed public/human/production-derived meanings. Public labels
   remain provenance, never product truth.
4. Produce hundreds of thousands of genuinely distinct renderings using human
   speech, permissioned production-derived structures, reviewed public wording,
   deterministic transformations, and externally generated candidates. Record
   generator/model/version, seed, lineage, phenomena, and preservation status.
5. Reach millions only with controlled perturbations of that broad bank. Keep
   every compact actual/expected delta in SQLite, partition by rendering hash,
   and freeze all config/probe/data hashes.

## Saturation gates

At 100, 1K, 10K, and every subsequent 100K, record:

- new semantic families;
- new semantic feature combinations;
- new normalized rendering structures;
- new normalized directional failure signatures;
- new broad failure families;
- marginal failures per 10K and 100K;
- marginal novel failures per compute hour.

Stop expanding a stratum when it adds no semantic family/combination, no
rendering structure, and no failure family across two checkpoints, or when
novel failures per compute hour falls below the campaign's declared threshold.
Shift budget to uncovered dimensions. Never infer user accuracy from synthetic
consistency.

## Promotion ladder

Use the smallest instrument capable of answering the question:

`diagnostic (64)` → `focused phenomenon/family` → `broad (1K–10K)` →
`partitioned stress (explicit N)` → `sealed aggregate benchmark`.

Do not replay millions after routine edits. A large replay is warranted for a
major parsing/runtime change or a specific prevalence question that smaller
runs cannot answer.
